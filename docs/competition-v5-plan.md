# Competition V5 implementation plan

Audit (2026-11-01): live MC Robot demo is local React state; presentation renders MapPrompt, not that state. Official Robot submits only after a client-side success and uses a command hash as idempotency key; failed runs are unrecorded. Existing canonical retry retains the highest score without penalties. V4 draft changes quantities to 6/4, while last verified production baseline is 4/3. State projection draft exposes the leaderboard before publication. No production access is needed for implementation.

1. Add a new V5 migration after the pending display-sync patch. Preserve pre-V5 functions, results and scoring via a rules_version frozen on new competition creation. New competitions require 6 questions/4 levels; legacy instances continue their original lifecycle/scoring/ranking.
2. Extend canonical attempt records with trusted executed/optimal counts and optimization marker. A V5 Robot branch in process_submission locks competition -> stage -> room -> round -> team, revalidates capability, replays idempotency, counts canonical runs and charges at most two explicit post-success optimizations. Write attempt, best solution and reduced score in one transaction; aggregate trigger handles negative deltas.
3. Derive explanations from attempts/submissions and finalized results. Private MC/own-team projections; public only after MC reveal. Exact integer weighted ranking then optimal-level count, fewer official Robot runs, perfect Accessibility, completed sudden deaths. Rules frozen per competition; never migrate old official results.
4. MC-only versioned demo RPC: server computes deterministic trace on a dedicated sample map, accepts bounded queue edits/run/pause/step/reset/explanation, stores running start offset; reads restore current step from server time. Poll 1s during live demo, 5s elsewhere, preserve cleanup/rate budgets. Spectator cannot mutate.
5. Ceremony state independent of frozen scores: ready -> intro -> ranking publication -> winner -> explanation -> closing; unresolved ties block publication. Public has no unpublished winner/ranking/explanation fields.
6. Extend existing MC/participant/presentation components, preserve QR/identity/design. Explicit official-run and paid Optimize Again controls, local debug steps free. Add score explanation and presentation ceremony components.
7. Execute real local PG17 concurrent/fault/authorization/regression tests, Deno/Vitest/build, independent-browser Playwright; capture and inspect required synthetic desktop/mobile screenshots.
8. Prepare migration/rollback/checksums and deployment guidance. No production SQL, function deploy or Vercel publish. Push a review branch in one batch so production main is not auto-published.
