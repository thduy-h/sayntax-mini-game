## Voice handling

When `speech.transcript` changes (via `useEffect` on `speech.transcript`),
and the transcript is non-empty:

1. Append to `voiceLog` (keep last 5)
2. `const intent = parseVoiceIntent(speech.transcript)`
3. Apply intent to workspace (see below)
4. After applying (or immediately for `run_program`), call
   `evaluateAndMaybeAdvance()` which:
   - Builds current `program` via `toProgram(workspace)`
   - If intent.kind is "run_program", `exec = executeProgram(program)`
     else uses a dummy success result: `{ success: true, output: [], errors: [], variables: {} }`
   - Calls `evaluateStepAction(currentStep.action, program, exec)`
   - Sets `lastFeedback` to the result's `feedback`
   - If `completed === true`: advance step (if not last), reset fail/feedback/skip
   - Else: `setFailCount(n => n + 1)`

## Intent → Blockly action mapping

Inside a helper function `applyIntentToWorkspace(intent: VoiceIntent)`
(defined at component-level with `workspaceRef.current` access):

- **add_block**: use the existing `addBlockFromVoice`-style pattern:
  ```ts
  const typeMap = { start: "scc_start", print: "scc_print", repeat: "scc_repeat", if: "scc_if", variable: "scc_variable" };
  const b = workspace.newBlock(typeMap[intent.blockType]) as Blockly.BlockSvg;
  b.initSvg(); b.render();
  const { x, y } = getInsertPosition(workspace); // copy from legacy file or inline
  b.moveBy(x, y);
  ```
- **insert_into**: find the first top-level block with type
  `intent.parentHint` (if provided). If found, and its first
  `input_statement` exists, create a child block of type... but we don't
  know child type from the intent alone (childHint is undefined in V1).
  For S5b, only handle the case where the learner says "đặt vào trong khối lặp"
  AFTER the child block already exists as a top-level block: find the
  most recent top-level child of a compatible type (print is the default
  child type) and connect it. If no suitable child exists, show a
  feedback message "Hãy thêm khối con trước" and don't change workspace.
  SIMPLIFICATION: if this gets too tangled, just do a no-op and
  `setLastFeedback("Đang thêm vào trong khối — hãy dùng chuột để kéo thả nếu cần.")`.
  The loose-pass semantics of `evaluateStepAction` insert_into will rely
  on the learner doing it via mouse OR already having nested blocks via
  starterWorkspace. That's acceptable for S5b — voice-driven insert_into
  is hard and can wait.
- **set_text**: find the currently SELECTED block in Blockly via
  `Blockly.common.getSelected()`. If none, show feedback
  "Hãy chọn khối trước khi đặt chữ." If a block is selected and has a
  field matching the currentStep.action's field name (or the default
  "TEXT"/"NAME" Blockly field names), set the field value via
  `block.setFieldValue(intent.text, fieldName)`. Helper to resolve
  target field from the current step action: if the step action is
  `set_text` with a specific `blockId` + `field`, prefer setting THAT
  block's field directly (find by blockId in the workspace via
  `workspace.getBlockById(blockId)` mapping). Otherwise fall back to the
  selected block.
- **set_number**: same logic as set_text but `String(intent.value)` into
  the field. For step-targeted number fields, use the step action's
  `blockId` + `field`.
- **run_program**: no workspace mutation. The evaluate step will run
  `executeProgram`.
- **ask_hint**: cycle through `currentStep.hints` (state: `hintIndex`),
  show the next hint in the hints card. Do NOT call evaluateStepAction
  here — ask_hint's evaluator always returns completed true, which would
  auto-advance unfairly. Special-case: if current step's action kind is
  "ask_hint", do call the evaluator (that's the intended completion
  path).
- **unknown**: show feedback `"Chưa hiểu câu lệnh. Thử nói lại hoặc nhấn ${intent.reason}."`
  with reason translated minimally:
  - "empty" → "im lặng"
  - "no_match" → "rõ hơn"
  - "ambiguous" → "rõ hơn"
  - "partial_add_block" → "thêm khối gì"

export function parseVoiceIntent(transcript: string): VoiceIntent;

# Normalization pipeline (apply to transcript BEFORE matching)

1. If empty/whitespace only → return `{ kind: "unknown", reason: "empty" }`.
2. Build `normalized` string:
   - trim
   - lowercase
   - reuse `stripVietnameseDiacritics` from `./index` (import it — DO NOT
     redefine; if it is not exported, add a NEW export keyword to it in
     `index.ts` as your ONE allowed edit, OR duplicate the 4-line function
     in the new file — Codex chooses; duplicate is cleaner, prefer that)
   - strip surrounding punctuation `[.,!?;:"'()]`
   - replace non-`[a-z0-9\s]` with space
   - collapse multi-space to single space
   - drop leading politeness: `(hay|lam on|giup minh|cho minh)\s+`
   - drop trailing politeness particles `\s+(di|nhe|nha|a|voi|oi)$`
   - final trim
3. Also keep the ORIGINAL transcript (post step 1 trim only) for `set_text`
   capture preservation — required so diacritics + case survive.

# Matching priority (FIRST match wins, don't try lower tiers)

1. **set_text** — regex on normalized:
   `/^(?:dat chu|go chu|noi dung la|cho chu|viet chu|chu la)\s+(.+)$/`
   If match: compute the captured text from the ORIGINAL transcript using
   whitespace-token alignment. Split both the original and normalized
   transcripts on whitespace. Count how many tokens the keyword phrase
   occupies in the normalized form (e.g. `"dat chu"` = 2 tokens,
   `"noi dung la"` = 3 tokens). Take the corresponding SUFFIX of the
   original transcript's tokens and join with single spaces. Return
   `{ kind: "set_text", text: <preserved> }`.

2. **set_number** — regex on normalized:
   `/^(?:dat so|gia tri(?: la)?|cho so|dat bang|so la|gan bang)\s+(.+)$/`
   Capture the numeric payload. Resolve in this order:
   - If payload matches `^\d+$` → `Number(payload)`
   - Else try the Vietnamese word-number table (see next block)
   - Else → `{ kind: "unknown", reason: "no_match" }`

   **Vietnamese number words** (exhaustive for 0..99; higher out of scope):
   - `khong=0, mot=1, hai=2, ba=3, bon=4, nam=5, sau=6, bay=7, tam=8, chin=9, muoi=10`
   - `muoi <unit>` = 10 + unit (special: `lam`=5 in this position, so
     `muoi lam` = 15, but `muoi mot` = 11, `muoi nam` = 15 also)
   - `<tens> muoi` for 20–90 where tens ∈ 2..9 (`hai muoi` = 20, `ba muoi` = 30, ...)
   - `<tens> muoi <unit>` for compound (`hai muoi mot` = 21; special
     `mot→1`, `lam→5`, `tu→4`, `nam→5` in unit position)
   - Implementation hint: write a small `parseVietnameseNumber(s: string): number | null` helper inside the file.

3. **insert_into** — normalized transcript starts with (or equals) any of:
   `dat vao trong`, `bo vo`, `cho vao ben trong`, `keo vo`, `dat vao`,
   `bo vao trong`, `long vao`, `nhet vao`
   After the keyword, if remaining tokens contain a block keyword
   (`lap`, `dieu kien`, `in`, `bat dau`, `bien`), set `parentHint` to the
   corresponding `BlockKind`: `lap→repeat`, `dieu kien→if`, `in→print`,
   `bat dau→start`, `bien→variable`. Otherwise `parentHint` undefined.
   `childHint` stays undefined in V1 (not parsed yet).

4. **add_block** — for each of the 5 BlockKinds, try its phrase list:

   - `start` (BlockKind `"start"`): `them khoi bat dau`, `them start`,
     `cho khoi bat dau`, `keo khoi bat dau ra`, `them lenh bat dau`,
     `khoi bat dau`
   - `print` (BlockKind `"print"`): `them khoi in`, `cho khoi in`,
     `them lenh in`, `them in`, `khoi in`, `in ra`
   - `repeat` (BlockKind `"repeat"`): `them khoi lap`, `cho khoi lap`,
     `them vong lap`, `them lap`, `khoi lap`, `lap lai`
   - `if` (BlockKind `"if"`): `them khoi dieu kien`, `them if`,
     `them dieu kien`, `khoi dieu kien`, `them khoi neu`, `neu thi`
   - `variable` (BlockKind `"variable"`): `them bien`, `tao bien`,
     `bien moi`, `them khoi bien`, `khoi bien`, `them mot bien`

   Matching: exact equality OR startsWith (strip trailing tokens then
   retry) — whichever is simpler; longest matched phrase wins.
   Return `{ kind: "add_block", blockType: <kind> }`.

   If the transcript contains a hint word (`them`, `cho`, `keo`) but
   NO block keyword matches → return
   `{ kind: "unknown", reason: "partial_add_block" }`.

5. **run_program** — exact/startsWith match on any of: `chay chuong trinh`,
   `chay di`, `thuc thi`, `run program`, `chay thu`, `chay code`,
   `bat dau chay`, `chay`

6. **ask_hint** — exact/startsWith match on any of: `goi y`, `chi toi`,
   `mach nho`, `giup voi`, `meo`, `huong dan`, `toi can goi y`,
   `cho xin goi y`, `xin goi y`

7. **unknown** fallback — `{ kind: "unknown", reason: "no_match" }`.

Note: because `set_text` and `set_number` are regex-anchored, they catch
those exact phrasings first. `add_block` matches are string-level (no regex
payload). Simple string comparison is fine.

## Per-variant pass rules (match the design spec exactly)

Helper: import `flattenBlocks` from `./helpers` for recursive block search.
Do NOT redefine it.

### add_block
`flattenBlocks(workspace.blocks).some((b) => b.type === action.blockType)`
→ pass. Loose per charter — disconnected block groups DO count.

### insert_into
`flattenBlocks(workspace.blocks)` has some block `p` with
`p.type === action.parentBlockType` AND `p.children` is a non-empty array
AND `p.children.some((c) => c.type === action.childBlockType)`.
Ignore `action.slot` in V1 (reserved for future). If NO parent of that type
exists, fail.

### set_text
Find a block in `flattenBlocks(workspace.blocks)` whose `id === action.blockId`.
If not found → fail. Read `block.fields?.[action.field]`. If undefined or not
a string → fail. Pass if
`String(fieldValue).trim() === action.expectedText.trim()` (exact,
case-sensitive, NO diacritic stripping).

### set_number
Find a block in `flattenBlocks(workspace.blocks)` whose `id === action.blockId`.
If not found → fail. Read `block.fields?.[action.field]`. Coerce via
`Number(fieldValue)`. Pass if `Number.isFinite(n) && n === action.expectedNumber`.

### run_program
If `executionResult.success !== true` → fail. If `action.expectedOutput` is
undefined → pass. Otherwise:
`executionResult.output.length === action.expectedOutput.length` AND
every index `i` passes
`normalizeText(executionResult.output[i] ?? "") === normalizeText(action.expectedOutput[i])`.
Use `normalizeText` from `./helpers`.

### ask_hint
Always `{ completed: true, feedback: ASK_HINT_PASS_FEEDBACK }`. No failing
state — this action exists only as an onboarding step to teach learners
that hints are available.
