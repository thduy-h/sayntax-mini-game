# Title
R1.3: Update lesson 5 step 6 seed to use variable_get reporter (closes "print variable" gap)

# Goal
With R1.1 (data-model reporter support) and R1.2 (Blockly wiring) in
place, the V1 limitation noted in the lesson-architect spec —
"V1 action model can't express 'print variable value'" — is no longer
true. Update lesson 5 ("Cơ bản về biến") so the final step actually
prints the variable's value (10) instead of a literal label.

This is the SMALLEST possible behavioral payoff slice that exercises
the new reporter system end-to-end.

# Files to modify

**MODIFY**: `packages/lesson-engine/src/seed-v2.ts`

Two changes within the same file:

## Change 1: lesson 5 step 5 (set print to use variable reporter)

Currently step 5 is "Đặt nhãn cho khối in" which has the learner type
the literal text "diem" into a print field. With reporters available,
this step is now redundant — and confusing. Replace it with a step that
SETS UP the variable reporter inside the print block via voice.

OLD step 5 (in lessonsV2 array, lesson index 4 = lesson 5, steps[4]):
```ts
{

  instructions: "Chọn khối in và hãy nói: **Đặt chữ diem** để ghi nhớ biến bạn đang theo dõi.",
  hints: [...],
  action: { kind: "set_text", blockId: "v2-l5-print", field: "text", expectedText: "diem" },
  starterWorkspace: { ...starter with empty text print... },
}
```

NEW step 5 — change to a `set_text` step that asks the learner to drag
a "biến diem" reporter into the print's text slot. Since we don't yet
have a voice intent for "drag reporter", the simplest correct
formulation is to seed the print block in the starter ALREADY
containing a variable_get reporter (so the workspace LOOKS done) and
then have the learner adjust it. But that's not satisfying as a step.

ALTERNATIVE: keep step 5 as a `set_text` step, but change `expectedText`
to a literal value the learner can speak ("xem điểm"). And keep the
"print the value" mechanic as a SEPARATE thing in step 6.

Actually, the cleanest minimal change is:

1. KEEP step 5 unchanged (it currently sets the print text to the literal
   "diem"). It's still a meaningful step.

2. ONLY change step 6 (the run_program step) so that:
   - The starterWorkspace's print block has `inputs.text = { type: "variable_get", fields: { name: "diem" } }` INSTEAD of `fields: { text: "diem" }`. This means by step 6, the print block has been "upgraded" from literal to reporter — implying step 5's outcome is actually wired through.
   - The action's `expectedOutput` is set to `["10"]` (the value of the diem variable, which is 10 from step 3).

Wait — but if step 5's eval is `set_text(expectedText: "diem")` against
a workspace where the print block has `inputs.text = variable_get(name="diem")`
(no `fields.text`), then `evaluateStepAction` set_text branch will
look for `fields.text` and find undefined → fail. Step 5 will be
unreachable.

So step 5 ALSO needs to change OR step 5's starter must keep
fields.text and step 6's starter is the one that switches to inputs.

CLEANEST minimal-change approach:

- Step 5 keeps `set_text(expectedText: "diem")` and its starter has
  the print with `fields: { text: "" }` (existing). Learner says
  "Đặt chữ diem" → print text becomes "diem" → eval passes → advance.
- Step 6 starter is updated: print block now has
  `inputs: { text: { id: "v2-l5-print-var", type: "variable_get",
  fields: { name: "diem" } } }` and NO `fields.text`. The action stays
  run_program but now has `expectedOutput: ["10"]`.

This way:
- Step 5 still works (set_text on literal field).
- Step 6 starter shows the print with a "biến diem" reporter dropped in.
- Running the program produces output ["10"] because executeProgram
  resolves the print's text via inputs.text -> variable_get(name="diem")
  -> variables["diem"] = "10" (set in step 3).

Also update step 6's title and instructions so it's clear the learner
is now USING the variable, not just labeling it:

- title: "In ra giá trị của biến"
  (was: "Chạy chương trình")
- instructions: "Hãy nói: **Chạy chương trình** để in ra giá trị của biến diem (sẽ là 10)."
  (was: "Hãy nói: **Chạy chương trình** để kiểm tra mọi thứ hoạt động.")
- hints (3 lines, Vietnamese):
  [
    "Khối in giờ chứa biến diem chứ không phải chữ.",
    "Giá trị của biến diem là 10 (đặt từ bước 3).",
    "Thử: Chạy chương trình."
  ]
